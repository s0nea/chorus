## Phase 0: Infrastructure

Set up everything needed so that any developer can write and run a test.

### 0a: Install `@pinia/testing`

```bash
yarn add -D @pinia/testing
```

### 0b: Create test setup file

**New file:** `ui/src/test-setup.ts`

- Global axios mock via `vi.mock('@/http/apiClient')`
- Minimal vue-i18n instance (tests need `$t` to not throw)
- Mock `useNotification` from `@clyso/clyso-ui-kit`

### 0c: Update vitest config

**File to modify:** `ui/vitest.config.ts`

- Add `setupFiles: ['./src/test-setup.ts']`
- Add coverage configuration (reporter: `text` + `lcov`)

### 0d: Add coverage script

**File to modify:** `ui/package.json`

- Add `"test:coverage": "vitest run --coverage"`

### 0e: Add CI workflow

**New file:** `.github/workflows/ci-ui.yml`

- Trigger: push to `main` + PRs, filtered to `ui/**` paths
- Steps: checkout, setup Node, `yarn install`, `yarn lint`, `yarn test:unit -- --run`

### 0f: Smoke test

**New file:** `ui/src/utils/helpers/__tests__/ApiHelper.spec.ts`

- One test for `getChorusAPIUrl` to verify the entire pipeline works (vitest runs, setup file loads, test passes)

**Commit 1:** `feat(ui): add unit test infrastructure`

## Phase 1: Helpers

Pure functions with no framework dependencies. Highest value-to-effort ratio.

### 1a: ReplicationsHelper

**New file:** `ui/src/utils/helpers/__tests__/ReplicationsHelper.spec.ts`

Test all 6 methods:
- `getLiveReplicationEventsDifference` — returns correct numeric diff
- `isLiveReplicationBehind` — true/false based on event counts
- `isReplicationStatusMatched` — each status filter maps to correct replication states
- `isReplicationCreateAtMatched` — date range matching
- `getDirectionPairString` — formats "storage1 > storage2"
- `getBucketPairString` — formats bucket pair, empty for user replications

### 1b: DiffReportsHelper

**New file:** `ui/src/utils/helpers/__tests__/DiffReportsHelper.spec.ts`

Test all 9 methods:
- `getDiffReportId` — deterministic ID from locations
- `getBucketPair` / `getDirectionPair` — formatting
- `isDiffReportStatusMatched` — each status filter
- `isTwoLocationReport` — boolean check
- `getStatusSortOrder` — correct ordering (0, 1, 2)
- `parseLocationFromQuery` / `formatLocationForQuery` — round-trip
- `parseQueryParamsToLocations` — multi-param parsing

### 1c: ErrorHelper

**New file:** `ui/src/utils/helpers/__tests__/ErrorHelper.spec.ts`

- `getReason` — extracts reason from Google RPC ErrorInfo structure, returns null for non-matching errors
- `getStatusCode` — extracts HTTP status from axios errors, returns null for non-axios errors
- `getValidationErrorMessage` — returns correct message per validation field type

### 1d: GeneralHelper

**New file:** `ui/src/utils/helpers/__tests__/GeneralHelper.spec.ts`

Skip lodash re-exports. Test custom functions only:
- `mergeWithCustom` — array concatenation behavior
- `formatBytes` — edge cases (0, KB, MB, GB, custom decimals)
- `formatDate` / `formatDateTime` / `formatDateDistance` — known date inputs
- `formatDurationSeconds` — parsing "123s" format

### 1e: LocalStorageHelper

**New file:** `ui/src/utils/helpers/__tests__/LocalStorageHelper.spec.ts`

- `get` — parses JSON, numbers, returns null for missing keys
- `set` — serializes values
- `remove` — removes key
- Mock `localStorage` (jsdom provides it, but verify isolation between tests)

### 1f: UptimeChartHelper

**New file:** `ui/src/utils/helpers/__tests__/UptimeChartHelper.spec.ts`

- `isPrometheusDataItemUp` / `isUptimeChartItemUp` — status checks
- `getTimestamp` — correct number extraction
- `getRawChartData` / `getRawChartDataMap` — transforms prometheus data correctly

**Commit 2:** `test(ui): add helper unit tests`

## Phase 3: Stores

All store tests follow the same pattern:
1. Create Pinia with `createTestingPinia()` from `@pinia/testing`
2. Mock `apiClient` responses for the endpoints the store's actions call
3. Call the store action
4. Assert store state

### 3a: Simple stores

**New files:**
- `ui/src/stores/__tests__/chorusRootStore.spec.ts` — `getProxy()` sets `proxy` state
- `ui/src/stores/__tests__/chorusStoragesStore.spec.ts` — `initStorages()` populates storages, `mainStorage`/`followerStorages` getters
- `ui/src/stores/__tests__/colorSchemeStore.spec.ts` — localStorage read/write, `isDark` getter
- `ui/src/stores/__tests__/i18nStore.spec.ts` — locale switching, localStorage persistence

### 3b: List stores with filters/pagination

**New files:**
- `ui/src/stores/__tests__/chorusReplicationsStore.spec.ts`
  - `getReplications()` → populates state from API response
  - Filter getters: status, bucket, direction, type, date range, user
  - Pagination getter
  - Bulk actions: `resumeReplications`, `pauseReplications`, `deleteReplications`
  - `clearFilters()` resets all filters
  - `$reset()` clears state

- `ui/src/stores/__tests__/chorusRoutingPoliciesStore.spec.ts`
  - Same pattern: fetch, filter, paginate, bulk actions

- `ui/src/stores/__tests__/chorusDiffReportsStore.spec.ts`
  - Same pattern: fetch, filter, paginate, bulk delete/restart

### 3c: Detail stores

**New files:**
- `ui/src/stores/__tests__/chorusStorageDetailsStore.spec.ts`
  - `initStorageDetails()` populates storage + credentials
  - Credentials filtering and pagination getters

- `ui/src/stores/__tests__/chorusDiffReportDetailStore.spec.ts`
  - `initDiffReportDetailsPage()` fetches report
  - `restartDiffReport()` calls API
  - `hasFixActivity` getter
  - 404 handling sets `isNotFound`

- `ui/src/stores/__tests__/chorusDiffReportEntriesStore.spec.ts`
  - `getReportEntries()` populates entries
  - Filtering by object name
  - Pagination getter
  - `inconsistentObjectsCount` getter

### 3d: Form/wizard stores

**New files:**
- `ui/src/stores/__tests__/chorusAddReplicationStore.spec.ts`
  - `initAddReplicationPage()` loads storages
  - `getBucketsList()` fetches buckets for selected storage
  - `createReplication()` — valid state calls API, invalid state does not
  - Step navigation via `steps` getter

- `ui/src/stores/__tests__/chorusAddDiffReportStore.spec.ts`
  - `initAddDiffReportPage()` loads storages
  - `createDiffReport()` — valid/invalid path
  - `findStorageToCompare()` logic
  - `validateCurrentStep()` per step

- `ui/src/stores/__tests__/chorusAddRoutingPolicyStore.spec.ts`
  - `addRoutingPolicy()` — valid/invalid path
  - `addBlock()` behavior
  - `isBlockOnly` getter

- `ui/src/stores/__tests__/chorusSetCredentialStore.spec.ts`
  - `initSetCredentialPage()` — new vs edit mode
  - `submitCredentials()` — S3 vs Swift credential shapes
  - `isS3` / `isSwift` getters

**Commits 4–7:** One per batch (see commit overview)
